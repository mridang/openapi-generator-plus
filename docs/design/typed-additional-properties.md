# Typed additionalProperties design (issue #103, item F15 of #131)

Status: proposal for owner review. Nothing here is built. This document fixes one behaviour for all twelve SDKs (java, kotlin, csharp, php, python, ruby, node, dart, go, rust, swift, elixir) so that no language is implemented first and the other eleven made to follow.

How it was grounded: issue #103 and #131 read with `gh`; the shared generator (`AbstractBetterCodegen.java`), the twelve `models/model.mustache` files, the object serializer templates, the twelve `Metadata` goldens and the twelve `Metadata` test templates were read. Where a claim names a file it was read there; where it says "not verified" nobody has run or read it. The pinned OpenAPI Generator is 7.12.0 (jar in the local Maven repository); `javap` on it shows that `CodegenModel` has `getAdditionalProperties(): CodegenProperty` and the public field `additionalPropertiesType`.

## Goal

A schema whose `additionalProperties` declares a value type (`Metadata` with `additionalProperties: {type: string}`) must surface in every SDK as a string-keyed map of that value type instead of a map of anything, so a caller reads `Map<String, String>` and never casts. Each extra value is decoded with the same strict codec and the same type checks as an element of a `Map<String, V>` property of the same schema, so a wrong value type fails the decode with the SDK's serialization error instead of passing through. This changes the public model API, so it lands in all twelve languages together with the twelve goldens, the catalogue and the documentation.

## Owner decisions that bind this work

- Clients only. No server and no database tags. `patternProperties` is declined (X11 in #131); only `additionalProperties` is in scope.
- Identical capabilities and the same API shape in all twelve; only idiom differs. A difference between two languages is a defect until a named language feature forces it (root `AGENTS.md`). The change lands in all twelve together (#103, `docs/decisions.md` "Typed values for `additionalProperties`"); no language is built first.
- No client-side validation. The checks added here are the decode checks every declared property already gets (JSON type, format codec, enum membership, model shape). Constraint keywords (`minimum`, `pattern`, `maxLength`, `minItems` and the like) are not checked on extras, exactly as they are not checked on declared properties. Construction through builders, constructors and `with` copies stays unchecked in the dynamic languages (python F316 `ApiModel` lenient `__init__`, ruby, php, elixir); the static languages get the check from their type system.
- Typed errors are thrown, never returned as values: a bad extra raises the SDK's `SerializationError` family (the error contract in the shared `generators/AGENTS.md`), and is never swallowed or turned into an `Any`.
- Native types where the language has one: `Map<String, T>`, `MutableMap`, `Dictionary<string, T>`, `Dict[str, T]`, `Hash`, `Record<string, T>`, `map[string]T`, `HashMap<String, T>`, `[String: T]`, `%{String.t() => T}` (see `docs/types.md`). Free-form values keep the existing any-type (`Object`, `Any?`, `object`, `JsonValue`, `AnyCodable`, `unknown`, `any`).
- Templates are Mustache files, never read a vendor extension that came from the input spec, and take generator-computed values only through `vendorExtensions` keys without an `x-` prefix. Structure is never built with string concatenation in Java.
- Never edit `.github/workflows`.
- The shared catalogue (`src/spec/resources/test-catalogue.txt`) has one id per behaviour; every language names a test with `bhv<id>` or has a documented line in `test-catalogue-exceptions.txt`. No new test files: extend the existing test templates (shared `generators/AGENTS.md`, "Test parity check").
- Goldens are never hand-edited; all twelve are regenerated and committed current, never a subset. The fixture cannot leak petstore vocabulary (`FixtureVocabularyLeakTest`).
- Documentation is part of the change: `docs/types.md`, `docs/decisions.md`, the twelve `docs/languages/<lang>.md` tables, the shared and per-language `AGENTS.md` files.
- Do not add a hard-wrapped PR description, a trailer or an attribution line (global instructions); the PR closes #103 with `Closes #103`.

## The shared behaviour

The promises, as catalogue lines. The file format is `areaNNN | promise` with an optional `| multi`; they are written here as `id: promise`. `models001` to `models011` already exist; the next free id is `models012`. The existing `models009` keeps its id and text ("Test additional properties are typed as string") and gets one meaning in all twelve (below); that is what lets the three exceptions disappear.

```
models009: The additional properties of a model whose additionalProperties schema declares a value type are exposed as a string-keyed map of that value type, not a map of any
models012: An additional property whose value has the wrong JSON type fails the decode with the SDK's serialization error
models013: An additional property whose value type is a model decodes to that model, and one whose value type is an array or a map keeps its element type
models014: A null additional property value is rejected unless the value schema is nullable
models015: A typed additional property is written back at the top level in its wire form (date-time, byte, enum), after the declared properties
models016: A free-form additionalProperties (true, an empty schema or no declared type) keeps accepting and returning any JSON value
```

Detail the lines stand for, so a test cannot be written to mean something weaker:

1. A value schema counts as typed when it has a `$ref`, a `type` or a non-empty `types` (this is the existing rule of `additionalPropertiesValueType` in `AbstractBetterCodegen.java`, read there). `additionalProperties: true`, `{}` and an absent keyword are free-form (`models016`). `additionalProperties: false` or absent on a model that has no bucket today still has no bucket; nothing changes there.
2. The value codec is the codec of a `Map<String, V>` property element in the same language. `date-time` extras are the date-time type with RFC 3339 and an offset, `byte` extras are base64 on the wire and the native bytes in memory (RF-25, which already requires this for map properties), enum extras reject unknown values, `int32` extras reject a fractional number and a value out of range, a model extra follows the model's own decode rules (required fields, nested extras).
3. A null value is rejected like a null element of a map of models or int32 (D65 and catalogue `serializationobject121` to `serializationobject123`), unless the value schema is nullable. Today ruby and elixir let a null through the typed path (`value.nil? ? value` in `ruby/object_serializer.mustache`, `is_nil(value)` in `elixir/object_serializer.mustache`); both change.
4. Encode is unchanged in shape: extras are written flat at the top level after the declared properties (D85), a declared property wins over a colliding extra and the key is written once (D63), numeric keys stay strings. Only the value is now written through the codec of its type.
5. The bucket is a map of the value type in the public API: read accessor, constructor or builder parameter, copy method (`with`, `copy`, `toBuilder`, `WithAdditionalProperties`, `with_additional_properties`), equality and hash (the shape of each is verified in the twelve goldens listed below).

## The shared generator changes

All in `src/main/java/io/github/mridang/codegen/generators/`, plus the fixtures and docs. The shared piece already exists in part: `AbstractBetterCodegen.populatesAdditionalPropertiesType()` (default `false`) and `additionalPropertiesValueType(schema)` fill `CodegenModel.additionalPropertiesType`, and only `BetterRubyCodegen` opts in (verified by grep: that is the only override). Eleven languages render a model whose `additionalPropertiesType` is empty, so they all print the any-type.

1. `AbstractBetterCodegen.fromModel` (around line 1929): fill `additionalPropertiesType` for every language, and also hand the templates a value node. A string is not enough for the languages whose decode needs the element kind (dart `deserialize_arg`, php `deserializeInternal`, node, swift, kotlin). Build the node with `fromProperty` for the value schema and put it in `vendorExtensions` under `additionalPropertiesValue` (no `x-`), with a boolean `hasTypedAdditionalProperties`. Templates then reuse the same partials they use for map elements (`{{#additionalPropertiesValue}}{{>deserialize_arg}}{{/additionalPropertiesValue}}` in dart). Do not name the key `additionalProperties`: templates already see the generator's option map under that name. Whether `CodegenModel.getAdditionalProperties()` is already populated for a model that also has declared properties is not verified; the first step is a one-model probe, and `fromProperty` is the fallback.
2. `additionalPropertiesValueType`: keep the free-form rule; decide composed value schemas (see risks). Carry nullability onto the node so a nullable value renders like a nullable map element.
3. Imports: when the value type is a model or enum, or an array or map of them, add it to the model's imports so languages with explicit imports (python, php, dart, node, rust, ruby) can name it. This is not verified: the golden `Metadata` files import nothing for extras today, and a model-valued bucket has never been generated.
4. Remove `populatesAdditionalPropertiesType()` and the `BetterRubyCodegen` override once the twelfth language is ready (it is a transition switch, not a permanent option). Until then each language flips it on in its own commit, together with its runtime and tests, so the build is never typed on the surface and untyped underneath.
5. Language hooks that exist today and may need the value type: `BetterJavaCodegen`, `BetterKotlinCodegen` (line 1299 uses `isAdditionalPropertiesTrue` for equality), `BetterPHPCodegen` (line 2149), `BetterPythonCodegen` (line 225, `setDisallowAdditionalPropertiesIfNotPresent(true)`, unchanged), `BetterElixirCodegen`, `BetterGoCodegen`, `BetterRustCodegen`, `BetterSwiftCodegen`, `BetterDartCodegen`, `BetterNodeCodegen`, `BetterCSharpCodegen`. ## Risks and open questions

1. Typing the surface without the runtime is a silent lie. Eight languages already render `{{additionalPropertiesType}}` in the template (java, kotlin, csharp, php, python, elixir, ruby, and the docblock in php), so turning the shared switch on compiles in several of them while the runtime stores untyped values: kotlin would hold a `Long` in a `MutableMap<String, String>`, and csharp would fail to build its type info. Recommended: never flip the shared default; each language turns on its own flag in the commit that also lands its decode and its tests, and the flag is deleted after the twelfth.
2. csharp, kotlin and node are the hard three. csharp is bounded by `[JsonExtensionData]` taking only `object` or `JsonElement` (not verified here), kotlin by a `@Transient` bucket filled by reflection, node by the TypeScript index-signature rule. Recommended: a one-day spike in each before the shape is fixed (the document gives the proposal for each in its row); if a spike fails, the answer is a different internal mechanism, not an exception to the public shape, because the owner rule is the same API in all twelve.
3. Value schemas that are not a plain `$ref` or `type`. A `oneOf` or `anyOf` value has no `type` and no `$ref`, so the current `additionalPropertiesValueType` returns null and the bucket stays any-typed; an inline object value with properties may or may not be hoisted to a named model by the pinned inline-model resolver (not verified). Recommended: probe both once; if the resolver hoists them they work through the model path, otherwise list composed and inline-object values as the one documented exception in `docs/types.md` and in `docs/decisions.md` (still free-form, as today) and open a follow-up issue, because naming and unions across twelve languages is its own decision.
4. Nullable values. A map property element that is nullable already has a per-language form (java and kotlin allow it in the map type, go `*V`, swift `V?`, rust `Option<V>`); the extras must use the same form, not a new one. Recommended: reuse the node's `isNullable` from the shared change and test it through `models014`; the exact per-language type of a nullable bucket value is not verified.
5. The public API of every model with a typed bucket changes type, so callers that cast break at compile time (java, kotlin, csharp, go, rust, swift, dart, node) or at the signature gate (ruby, python, php, elixir). `AGENTS.md` fixes the public shape so later features are additive; this is a deliberate break that #103 already accepts. Recommended: one release note and the version bump decided by the owner, in the release that carries the other pending breaking changes; no deprecation shim, because a shim would need both types in all twelve.
6. Go #107 (single-pass models) and the #122 public-surface guard overlap. #107 rewrites the unmarshal loop that this change edits. Recommended: land #103 first in the smallest edit of that loop, so #107 rebases onto typed values; compare the public members of the twelve by hand until #122 exists (root `AGENTS.md`).
7. Import and name resolution of a model-valued bucket in languages with explicit imports (python, php, dart, node, rust, ruby) has never been generated (shared change 3). Recommended: generate the `Roster` fixture first in those six and fix the imports before anything else.
8. Rust value codecs on a flattened map (`with =` for byte, duration, time, uri) are not verified, and `serialize_extras` must become generic. Recommended: spike with the byte and date-time fixtures; if `with =` cannot be applied to a flatten field, write one generic `serialize_with`/`deserialize_with` pair per codec in `object_serializer.mustache` and reference it from the model.
9. Test count and weight: five new fixture models and twelve languages makes sixty generated model files and tests per run. Recommended: keep the fixtures minimal (one declared property at most) and put the decode cases in the existing `ObjectSerializer` test template as table rows, not as separate tests per fixture.
10. Local regeneration is flaky for network formatters (php and swift drift). Recommended: regenerate all twelve goldens in one run on a clean tree and diff only the expected files before committing (shared `generators/AGENTS.md`, `DockerFormatter`).
