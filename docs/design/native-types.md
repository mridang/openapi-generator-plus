# Native types design (issues #126, #155, #156, #157)

Status: proposal for owner review. Nothing here is built. This document fixes one rule and one wire form for typed dates, durations, IP addresses, URIs and exact decimals in all twelve SDKs (java, kotlin, csharp, php, python, ruby, node, dart, go, rust, swift, elixir), so that no language is implemented first and the other eleven made to follow. Every claim about a language is marked "verified in <file>" (I read that file in this worktree, or ran the check locally) or "not verified" (taken from a docs page, from memory of the language's documentation, or not checkable here because the toolchain is missing). The toolchains present locally were node 24, python 3.9, swift 6.2 (macOS), java 22 and cargo; go, dotnet, dart, elixir, php, ruby 3.x and kotlin were not available, so their library behaviour is "not verified" unless a repo file shows it.

## 1. Goal

Every `format` that a language's standard library can represent natively (date, duration, IP address, URI, exact decimal) is exposed as that native type in the generated models, options and parameters, and a language without a native type keeps a documented fallback, so the same field reads the way that language's developers expect. The wire form of each format is one fixed text, identical in all twelve SDKs and independent of what the native type prints by itself, so the bytes on the wire never depend on the language. A value the SDK cannot parse fails with the SDK's `SerializationError` exactly as every other typed format does today, and never in a way that hides an HTTP error.

## 2. Owner decisions that bind this work

Taken from the owner's instructions for this task, issues #126, #155, #156 and #157, and the shared rules file (`src/main/java/io/github/mridang/codegen/generators/AGENTS.md`, "the shared rules" below).

1. Clients only, twelve languages, identical capabilities and the same API shape; idiom may differ, capability may not. A difference between two languages is a defect until a named language feature forces it (root `AGENTS.md`).
2. One rule for dates, durations, IP and URI, and decimals (#155, #156, #157 all say it): the native standard-library type where the language has one, otherwise a small value type or the plain type, said so in the table of `docs/types.md`.
3. No client-side validation (S3, D55, F316): nothing validates at model construction and the SDK does not enforce `pattern`, length or range. Wrong values are caught at the wire boundary, on decode, with `SerializationError`.
4. Typed errors are thrown, never returned as values; an enum or discriminator value the SDK does not know fails loudly (F835). The same rule is the precedent for a malformed `uri`, `uuid`, `date-time` and `duration`.
5. No servers; native types where the language has one; templates are Mustache files and never read a spec-sourced `x-*` extension. A flag the generator computes is handed to templates under a generator-owned `vendorExtensions` name without an `x-` prefix (root `AGENTS.md`).
6. The wire contract is shared (D57 date-time `YYYY-MM-DDTHH:MM:SS.SSS+00:00`, D62 `uri` is an absolute RFC 3986 URI written byte for byte, D81 `time`, D83 bare `type: number` exact and in plain notation, D88 protobuf durations of up to 315,576,000,000 s). This design extends that contract and does not reopen any of it.
7. Node `format: date` is a validated `YYYY-MM-DD` string (F1082) and stays so.
8. A fix needs a test that fails without it, in the existing test templates (no new test file); one behaviour id per behaviour in `src/spec/resources/test-catalogue.txt`, and each language names a test from the id or lists a documented exception in `test-catalogue-exceptions.txt`. Never edit `.github` workflows from this repo (S13).
9. Goldens are regenerated, never hand-edited, and committed all twelve current (root `AGENTS.md`). A new dependency must be a small pure library, never one that needs a native binary (S10). A floor change is the owner's call (F1087).
10. The documentation tree is part of the change: `docs/types.md`, `docs/languages/<lang>.md`, `docs/decisions.md` and the generated README sections change in the same pull request.

Verified here: java `URI` and csharp `Uri` (`AbsoluteUriConverter` writes `value.OriginalString`, verified in `src/main/resources/templates/csharp/object_serializer.mustache`), and node `new URL()` does not (run locally: `https://example.com` becomes `https://example.com/`, `HTTP://EXAMPLE.com:80/a%2fb` becomes `http://example.com/a%2fb`, `'` becomes `%27`). - `hostname` and `email` have no native type that round trips: .NET's `MailAddress` accepts display names, and nothing in any standard library parses a hostname as a value. They stay strings; Node keeps its existing branded `Email` (verified in `docs/languages/node.md`).

These are the documented fallbacks the owner's rule asks for.

### 3.2 The wire rules (one form, whatever the native type prints)

R1. Date. Written `YYYY-MM-DD` (four-digit year, two-digit month and day). Read only in that form and only if it is a real calendar date; `2024-02-30`, `2024-1-5` and a date-time are rejected. The host clock and zone are never consulted (D57 extends to dates). The value is a calendar date, so a zone never shifts it (Go `models.Date` is stored at UTC midnight; Dart `DateTime` is UTC midnight, Node is the string).

R2. Duration. The protobuf-JSON form `-?[0-9]+(\.[0-9]{1,9})?s`, magnitude at most 315,576,000,000 s (D88). Written as whole seconds when the fraction is zero, otherwise with the fraction cut to 3, 6 or 9 digits, the smallest width that keeps every non-zero nanosecond (verified in `go/models/duration.mustache`, `python/_duration.mustache`, `node/object_serializer.mustache`, `rust/proto_duration.mustache`). Never ISO 8601. A native type that is coarser than a nanosecond keeps every digit it can hold and truncates the rest toward zero, never rounds and never rejects: python `timedelta` is microsecond (verified in `python/_duration.mustache`: `micros = nanos // 1000`), csharp `TimeSpan` is one tick of 100 ns (verified in `csharp/object_serializer.mustache`: `nanos / NanosPerTick`), dart and elixir are microsecond (not verified). A value outside the native range is a `SerializationError` that names the value, never a wrap (verified for csharp `checked(...)` and go range check; Go's range is about 292 years, a forced divergence already written as D88).

R3. IP address. A decoder accepts only the plain address text: `ipv4` is four dotted decimal octets with no leading zeros; `ipv6` is any RFC 4291 text. It rejects, in every language that has a native address type, leading zeros, a prefix length (`/24`), a zone id (`%eth0`), square brackets, surrounding whitespace, and the wrong family (an `ipv4` field given an IPv6 text). A language whose parser would accept these (Python's `ip_address` accepts a scope id, run locally on 3.9.6: `fe80::1%eth0` parses; go `netip.ParseAddr` accepts zones; .NET `IPAddress.Parse` accepts shorthand such as `1`, not verified) gets a strict pre-check in the SDK so the accepted set is identical. The encoder writes `ipv4` as dotted decimal and `ipv6` in RFC 5952 form (lowercase hexadecimal, the longest run of zero groups compressed). Because every native type canonicalises, `2001:0DB8:0:0:0:0:0:1` is read and written back as `2001:db8::1`: the value is preserved, the text is not (see Q1). The IPv4-mapped form (`::ffff:1.2.3.4`) is excluded from the pinned promise because its printed form is not stable even inside one language (run locally: Python 3.9.6 prints `::ffff:102:304`; whether 3.13 prints `::ffff:1.2.3.4` is not verified here).

R4. Decimal. A `type: number` value (bare, or `format: decimal`, which the generator maps to the same `number` key) is read from its JSON text without passing through a binary float, written as a bare JSON number in plain notation with no exponent (D83), and keeps its trailing zeros where the native type can (`1.50`). A `type: string` value with `format: decimal` or `number` (the generator maps both through the `decimal` key, verified in the `typeMapping.put("decimal", ...)` lines of the twelve codegens) is the same native type but travels as a JSON string and is rejected if it arrives as a JSON number. In a language with only a float the value is read and written as that float and the loss is documented in the README section "Decimal / `format: number` precision" (D83, FD-11). A number the native type cannot hold (csharp `decimal` has about 28 digits; `Foundation.Decimal` about 38; both not verified here beyond the Apple run below) is a `SerializationError`, never silently rounded.

R5. URI. D62 stands: an absolute RFC 3986 URI with any scheme, written exactly as read. A language uses a native URI type only if the whole corpus round trips byte for byte through that type: `https://example.com`, `HTTP://EXAMPLE.com:80/a%2fb?x=1&x=2#frag`, `mailto:a@b.c`, `urn:isbn:0451450523`, `https://example.com/[x]?q='a'`, `https://example.com?`, `https://example.com/%7euser`, `https://[2001:db8::1]:8443/`. Otherwise the field is a checked string. `uri-reference` and `uri-template` stay plain strings (verified in `AbstractBetterCodegen.keepStringForUriSubformats`).

R6. Failure behaviour on an unparseable value. A field whose type is a native type (or a checked string) that receives text the rule above rejects fails the decode with `SerializationError` naming the property and the value, the same as `uuid`, `date-time`, `duration` and `uri` do today (F316, F835, D80). A field that is a plain string never fails. The failure of an optional or nullable field is the same as a required one; a `null` is a null (F834). On an error response, a body that does not decode against the declared error schema leaves the status class with the raw body and the decode failure as its cause (shared rules, "The error contract"), so a bad IP in an error body never hides the HTTP error. Encode cannot fail for a native type, because a native value is valid by construction; the only encode failures are the ones that exist today (a Go duration or date outside the range of the type, a non-finite float).

R7. Parameters. A query, header, path, cookie or form parameter of these formats is written through the same canonical text as a body field (the shared `stringify` in each `ObjectSerializer` or `ValueSerializer`), so a `Duration` parameter is `3600s`, a date is `YYYY-MM-DD`, an address is its canonical text and a decimal is plain notation.

## 7. Risks and open questions

Only real ones. Each has a recommended answer.

**Q1. Native IP types cannot keep the server's text (the wire promise of #156).** #156 says the wire form "stays the exact text the server sent, so a value round-trips unchanged". Every native address type canonicalises: Python printed `2001:0DB8:0:0:0:0:0:1` as `2001:db8::1` (run locally), and Go, .NET, Rust and Erlang normalise too (not verified here). So "typed IP" and "byte-verbatim IP" cannot both hold for IPv6, and the printed form of an IPv4-mapped address is not even stable inside Python across versions. Recommended: keep the typed IP and pin the weaker promise "the address is preserved, the text is canonical RFC 5952", exact for IPv4 and for already-canonical IPv6, as R3 and catalogue id 406 say; revise the sentence in #156. The alternative is to keep `String` for IP in all twelve, which gives up the whole of #156 for IP and leaves only Kotlin's URI.

**Q2. A typed field fails the whole response on a bad value.** #156 asks that an unparseable value "must not turn a successful response into a failure" and to "decide per language whether the typed field falls back to a string or raises". A statically typed field cannot fall back to a string, and every typed format fails loudly today (`uuid`, `date-time`, `duration`, `uri`, F316, F835). Recommended: raise `SerializationError` for every typed format, including IP (R6), plain-string fields never fail, and an error response can still not be masked because an undecodable error body keeps the status class with the raw body (shared rules). A spec whose server sends sloppy addresses drops the `format`. This is a decision against the letter of #156 and needs the owner's yes.

**Q3. Go cannot expose a bare `time.Duration` or `time.Time` field.** The models marshal through `type Alias` and each field's own marshaller (verified), `encoding/json` writes `time.Duration` as integer nanoseconds and `time.Time` as RFC 3339 with `Z`, and containers of the bare type cannot be customised. Going bare would mean a generated per-model codec that replaces the `Alias` pattern, plus a codec for sets, slices and maps. ogen can expose `time.Duration` because it generates its own encoder per type, not `encoding/json`. Recommended: keep `models.Duration` and `models.DateTime`, and add `models.Date`, all defined types over the standard library type, convertible at no cost, and record it as a forced divergence (FD-24) so the type table says "defined type over `time.Duration`". Answer #126 with `models.Date` over `time.Time`, not a validated string: it matches `DateTime`, and a string would let a bad date reach the wire.

**Q4. Kotlin: `java.time.Duration` or `kotlin.time.Duration`; `Url` or `java.net.URI`.** Both duration types are standard-library types for a JVM-only SDK (verified in `docs/languages/kotlin.md`). `kotlin.time.Duration` is the Kotlin idiom, but it stores a 64-bit count and keeps nanosecond resolution only for about 146 years, which is far below the protobuf range of 315,576,000,000 s (about 10,000 years); not verified here. Recommended: keep `java.time.Duration` (exact over the whole range, the same as Java) and say it in the table; change `uri` to `java.net.URI` because `io.ktor.http.Url` is a library type that normalises and so breaks D62 (verified in `docs/languages/kotlin.md`).

**Q5. Swift: raise the platform floors for `Swift.Duration`.** `Duration` is exact (integer-backed) and fixes the `Double` seconds of `TimeInterval`, but it needs macOS 13 and iOS 16 (verified by compiling against macOS 12) while `Package.swift` says macOS 12, iOS 15, tvOS 15 and watchOS 8 (verified). Raising a floor is the owner's call (F1087). Recommended: raise to macOS 13, iOS 16, tvOS 16 and watchOS 9, delete FD-2 and the `TimeInterval` row of the idiom matrix, and add the new floors to `docs/languages/swift.md`. If the owner declines, Swift keeps `TimeInterval`, the exception stays, and `serializationobject404` for Swift pins the double rounding.

**Q6. `format: date` in Swift, and the wording of #126.** #126 says Go "is the only SDK left where a date parameter is a bare string", but `docs/types.md` lists Node, Go and Swift (verified, and the Swift exception for `serializationobject044` in `test-catalogue-exceptions.txt` says so). Node is decided (F1082). Foundation has `Date` (an instant) and `DateComponents` (unvalidated parts), neither of which is a calendar date. Recommended: keep Swift `date` as `String`, documented as the fallback, and open a follow-up for an SDK `LocalDate` only if the owner wants one; this work covers Go.

**Q7. Which float languages adopt a decimal library, and Swift `Decimal` on Linux.** The rule says the native type, otherwise the float with the documented loss, so php, dart, go, rust and elixir stay floats (section 3.1). S10 would allow a small pure library (`rust_decimal`, the `decimal` hex package, `\BcMath\Number` at PHP 8.4), but each needs a reader change (`serde_json` `arbitrary_precision` is a global feature the review advises against; Jason needs `floats: :decimals`; PHP needs a floor raise). Recommended: do not adopt a library in this work; file one follow-up issue per language if wanted. For Swift, `Foundation.Decimal` decodes and encodes exactly on macOS (verified), but the SDK is built and tested on Linux with swift-corelibs-foundation (not verified). Recommended: run the Swift Linux gate first as a spike with ids 410 to 412; adopt `Decimal` only if it passes, otherwise keep `Double` with the documented loss and keep the exception for id 002.

**Q8. Ruby free-form numbers change type.** `JSON.parse(..., decimal_class: BigDecimal)` applies to every fractional number, so an untyped object or `additionalProperties` value that is `Float` today would become `BigDecimal`, a public behaviour change. Recommended: parse with `decimal_class` only to read typed `number` fields and convert back to `Float` for `AnyType`, free-form objects and `additionalProperties`; add a test for the free-form case under id 410. Not verified: that `decimal_class` is available in the `json 2.6` the gemspec declares.

**Q9. The string-shaped decimal wire is not verified anywhere except Node.** `type: string, format: decimal` maps to the same decimal type as `type: number` (the generator uses one `decimal` key), but the wire shape differs (a JSON string) and only Node has a flag for it (`isDecimalFormat`, verified in `node/models/model.mustache`). Java's Jackson writes a `BigDecimal` as a number, so Java and Kotlin may already be wrong (not verified). Recommended: the fixture field `ledger` and id 411 find out; fix every language that fails in the same change, using the shared `isDecimalString` flag.

**Q10. `\DateTimeImmutable` is a public type change in PHP.** Every `date` and `date-time` field and parameter changes type. Recommended: do it now, with the other public-type changes, because the SDK is pre-release (the "Rebuild" milestone), the models are `readonly` and a mutable value inside defeats F868, and `time` already uses the immutable class.

**R-a. Catalogue ids can be satisfied by a weak test** (verified for Swift and Python on id 002, section 3.3). A new id is only closed by a test that uses the petstore corpus in section 3.3, and a reviewer checks each language's assertion, not the presence of the id.

**R-b. Library behaviour I could not run.** Go `netip`/`url`, .NET `IPAddress`/`decimal`, Rust `Ipv6Addr`/`url::Url` serde, Dart `Uri`, Elixir `:inet`/`URI`/`Duration`, Ruby `IPAddr`/`URI`/`decimal_class`, Swift on Linux, and PHP are "not verified". The mitigation is the order below: each language's first commit is the corpus spike (ids 407, 408, 412), run in that language's container, before any template change; a row that fails keeps the string fallback and changes the table, not the rule.

**R-c. Eleven goldens plus Docker formatters.** Regenerating after a shared change is flaky locally (spurious php and swift drift; shared rules). Commit all twelve goldens current in every batch and read CI per job.
